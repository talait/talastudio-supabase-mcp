# talastudio-supabase-mcp

- Commit messages in English.
- This Worker serves ONLY `mcp.talastudio.net`: `/mcp`, `/.well-known/oauth-*`, `/.well-known/openid-configuration`, `/oauth/register`, `/oauth/token`, `/oauth/authorize`, and `/upload/<ticket>` (one-time file upload addresses from `upload_attachment`: PUT streams the original file to Drive, GET shows a small drop page; the ticket is the only permission — one account, 60 minutes, one file, hash stored in `mcp.upload_tickets`), and `/download/<ticket>` (one-time addresses from `open_original` / `look_at_file` with a page: GET streams the ORIGINAL company file, Google-native files exported to PDF/XLSX, to Claude's code sandbox; one account, 30 minutes, 3 downloads, hash in `mcp.download_tickets`; HR files only for admins/`access.hr`, checked before the ticket is made). Every other path is 404. It has no Cloudflare Access in front, so it never trusts `cf-access-*` headers and never serves workspace pages.
- Company records are read-only. The only writes (owner decision 20 Nov 2026) are the shared context: team/personal notes (`remember`/`forget` via `mcp.note_*`, the same notes James reads), conversations (every tool call's `user_message`/`previous_answer` and `save_chat` → `mcp.chats`/`mcp.chat_turns`, append-only, published to `ai.documents` source `ai_chat`), and files saved to Drive `TALASTUDIO ASSETS/_CLAUDE/<person>/<date>` (`save_file` for text Claude writes; `upload_attachment` + `/upload/<ticket>` for original attachments and sandbox files, decision 20 Nov 2026; logged in `mcp.saved_files`). Project spaces (owner decision 23 Nov 2026, "kita perlu upgrade mcpnya"): one shared context per project for every Claude account — `mcp.projects`, `mcp.project_docs` (INSTRUCTIONS, BRIEF, working docs; every write is a new version), `mcp.project_decisions` and `mcp.project_sessions` (append-only hand-overs), `mcp.project_visits`; tools `project_list`, `project_open`, `project_read`, `project_write`, `project_decide`, `session_end`; project files go to Drive `TALASTUDIO ASSETS/_PROJECTS/<project>/files` (`mcp.saved_files.project`); docs are published to `ai.documents` source `claude_project`. Never overwrite saved conversations or files. Never overwrite project document versions. Do not add tools that change company records, send, approve or delete without an explicit owner decision.
- Never expose secrets: `core.app_secrets`, `core.settings` (use `mcp.settings_public`), alert webhooks, extension/agent releases, WhatsApp QR/pairing state, upload session URLs, and other people's James chats/notes. Every tool result goes through `redact()` (the one exception: `upload_attachment`, whose result is only our own one-time `/upload/<ticket>` addresses); SQL rows through `hideSecretKeys()`.
- Who may connect: `core.settings` `access.mcp_domains` (company domains) and `access.mcp` (single emails) in Supabase, never hardcoded emails.
- `src/james/tools.ts` and `google.ts` are copies from the workspace repo (`talait/talastudio-supabase`, `app/src/lib/`). Change them there, then `npm run sync-james`.
- Database changes go as migrations in the workspace repo (`supabase/migrations`), not here.
- Pin dependency versions; run `npm run typecheck` and `npx wrangler deploy --dry-run --outdir dist` before pushing.
